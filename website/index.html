Core Knowledge Base

Why Financing Apps Lock Devices

Financing lock applications (such as ShopUp, PayJoy, or Knox Guard) do not rely on standard user app permissions. They integrate directly into the Android System Policy Framework.

Device Owner Privileges

The lock agent is registered as a Device Admin or Device Owner (`dpm`). This allows it to block factory resets, disable developer mode, and render un-dismissible full-screen system overlays.

Hardware Root of Trust

Advanced platforms like Samsung Knox Guard bind device compliance to hardware eFuses and Serial/IMEI cloud attestation. Hard resets won't remove locks if the cloud flags installment defaults.

ADB & Package Inspection

This open-source lab documents how researchers analyze active package states, inspect policy manager configurations, and audit device management boundaries safely.

System Stack Analysis

Android Security Layer Architecture

System Overlay & Screen Lockdown

TYPE_APPLICATION_OVERLAY / SYSTEM_ALERT_WINDOW

Financing lock applications draw an inescapable view over all other system windows when an installment is overdue. This window intercepts touch events, hides the status bar, and prevents launching the System Settings menu or other applications.

Persistent MDM Agent

Foreground Services & Boot Receivers

The MDM client maintains a high-priority foreground service with persistent sticky intent receivers (`BOOT_COMPLETED`, `PACKAGE_REPLACED`, `LOCKED_BOOT_COMPLETED`). It continuously monitors connectivity and syncs compliance signals with remote cloud endpoints.

DevicePolicyManager (DPM) Framework

Android Enterprise Management API

The Device Policy Manager provides systemic control over OS features. Once granted `DeviceOwner` status, the application can set restrictions such as `DISALLOW_FACTORY_RESET`, `DISALLOW_DEBUGGING_FEATURES`, and `DISALLOW_SAFE_BOOT`.

Hardware eFuse & OEM Cloud Attestation

Samsung Knox Guard / Play Integrity API

Hardware-level MDMs link device IMEI and serial numbers directly to OEM enrollment servers. Even if a device is completely re-flashed via factory firmware, the hardware attestation process triggers re-enrollment automatically during setup wizard network initialization.

echo "[+] Inspecting USB Debugging restriction flags..."
adb shell settings get global adb_enabled

# ADB Privilege State Checker (Python PoC)
import subprocess

def check_device_owner():
    try:
        output = subprocess.check_output(["adb", "shell", "dpm", "status"]).decode()
        print("[+] DPM Status Output:\n", output)
    except Exception as e:
        print("[-] ADB Connection Failed:", e)

if __name__ == "__main__":
    check_device_owner()
